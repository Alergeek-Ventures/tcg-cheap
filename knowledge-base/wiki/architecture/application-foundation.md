## Current state

TCG Cheap is a Phoenix LiveView application using the `TcgCheap.Core` Ash domain and `TcgCheap.Repo` AshPostgres repository. The local catalogue includes `CardSet` and exact-identity `CardPrinting` storage, with metadata, legalities, assets, source payload, sync timestamps, and conservative Cardmarket mapping state. `CardSet` is nullable for legacy/minimal records. The active TCGdex aggregate is a background-acquisition boundary; it is not called by public rendering or events, and no seller/offer count is fabricated.

Phase 4 has a canonical source-neutral sealed foundation. `SealedProduct` models stable canonical slugs, normalized name/search text, allowlisted product types, series/set/release, optional finite positive PLN MSRP with paired provenance/source URL, image, official PL/en flags, draft/approved/archived publication, current/discontinued state, source identity/provenance/private payload, and timestamps. Source imports are draft-only, keyed by stable source/source ID, may correct draft slugs, and cannot overwrite reviewed rows; manual curation can omit source. Approval enforces released/non-future and official PL/en completeness. Discontinued approved products remain readable; archive is soft/unpublished. `SealedProductAlias` models normalized name/EAN review values with original values/provenance, pending/approved/rejected queues, and approved-per-product reads. GTIN-8/12/13/14 ASCII normalization and GS1 checksum are enforced in app and DB, with canonical-product global uniqueness. Imports are pending-only/idempotent and cannot overwrite reviewed aliases.

The foundation now also includes `Retailer` regular-retailer/LGS identity, a source-neutral `SealedRetailerAdapter` normalized contract, `RetailerListing` as the active local current projection, conservative exact-approved-GTIN `SealedListingMatcher`, and one reviewable `ListingProductMapping` per listing. Mapping imports can update only pending/review rows; matched/rejected decisions are locked and protected from source overwrite, and matched targets must remain eligible approved Polish-English products. One fixture-backed LootQuest adapter now exercises the retailer-specific contract and refresh machinery, but it is deliberately absent from default runtime configuration because recurring collection/republication permission is unresolved. There is still no approved production feed/access, live sealed schedule, or real retailer row.

`SealedListingObservation` is immutable PLN price/stock/source history appended in the same transaction as a successful listing ingest. A stable per-retailer/source-listing advisory lock closes the concurrent first-insert upsert race and remains held through observation recording. Stale `last_seen_at`/`last_checked_at` input cannot regress the projection. Unchanged later checks advance projection audit timestamps without duplicate history; changed title/URL/GTIN/Decimal price/stock/payload appends, including transitions back to a prior state. One observation is allowed per listing/provider check timestamp, ambiguous same-timestamp changes roll back, and restrictive foreign keys prevent observation loss through hard listing deletion. App and DB constraints enforce HTTPS, normalized titles, valid GTINs, PLN-only finite positive optional prices, in-stock price presence, stock states, identities, and timestamp ordering.

`SealedRetailerRefresh` completes provider fetches before writes, revalidates at most 1,000 normalized JSON-safe listing values, rejects malformed/duplicate batches before persistence, and locks/revalidates the canonical active retailer before atomically ingesting the full batch while dispatching Ash notifications only after commit. A retailer disabled during fetch cannot receive later writes, and a failed later row rolls back earlier writes. Missing rows remain untouched rather than becoming fabricated sold-out transitions. `SealedRetailerAcquisition` accepts only a canonical active retailer and an explicitly configured source-key adapter; `SealedRetailerWorker` uses active-state uniqueness on retailer/source, queue concurrency one, a finite six-minute execution timeout, bounded retry/backoff and Retry-After handling, and permanent/transient failure separation. The adapter registry is empty by default and no sealed Cron exists.

`SealedRetailers.LootQuest` is a disabled-by-default fixed-host WooCommerce Store API adapter proven against a time-specific fixture. It requests only listing identity, price, category/tag, purchasability, stock, and backorder fields; bounds pagination, response bytes, redirects, options, total rows, per-request time, and whole-job time; preserves exact requested source payload; decodes source title entities; accepts only strict LootQuest product URLs; converts minor-unit PLN with Decimal; and does not infer GTIN from retailer SKU. Req-level retries are disabled so Oban owns bounded whole-batch retries, including transient page-count drift. Explicit category plus import/preorder/backorder filtering reduces obvious false positives, but the public source does not positively establish released English official Polish distribution. No row can become a public offer without canonical approved product/mapping review, and live use remains blocked on written retailer permission.

Product/alias/mapping review transitions use transaction-local row locks and revalidate latest state/completeness under lock. Human review now additionally requires the displayed `updated_at` version, preventing stale product edits, approvals, archives, alias decisions, or mapping decisions from acting on newer evidence. Generated migration/snapshot sets `20260808160842_sealed_catalogue_foundation`, `20260808204902_sealed_retailer_listing_foundation`, `20260808213452_sealed_listing_observations`, the `20260808231641`/`20260808231642` administrator-authentication pair, and `20260809003932_public_sealed_lookup` were reviewed; the generated authentication-extension rollback was narrowly corrected to retain shared pre-existing Ash functions. No production SKU, retailer, listing, observation, configured live adapter, invented price/history, benchmark, graph, or buying band was added. Phase 4 now extends through a public local-data projection but remains blocked on real acquisition and curation.

`TcgCheap.Accounts` now provides the restricted administrator identity and persisted AshAuthentication token resource. There is no public registration route: `mix admin.provision` reads a bounded email/password only from environment variables. Password sign-in renews and clears the prior session before storing the token; sign-out revokes tokens and disconnects the LiveView socket. Production reuses `SECRET_KEY_BASE` unless a separate minimum-32-byte `ADMIN_AUTH_SIGNING_SECRET` is supplied; development reuses its endpoint secret through a non-secret sentinel and tests use isolated configuration. Sign-in attempts are atomically limited by both remote IP and normalized bounded email, with a fixed-window entry cap, periodic expiry, and fail-closed overload behavior.

Authenticated `/admin/review` is a focused custom LiveView because the evidence-led approve/reject workflow is not generic CRUD. Admin-only Ash policies protect queue reads and human product/alias/mapping transitions independently of route plugs. The desk streams draft products, pending aliases, and pending/review listing mappings; preloads product/retailer evidence; supports product correction/approval/archive, alias approval/rejection, and mapping confirmation/reasoned rejection; and reloads every queue after a decision. AshBackpex remains required for the broader main CRUD/operations interface and is not implemented by this focused desk.

The NBP backend now adds an AshPostgres `ExchangeRate` resource as the canonical NBP Table A EUR/PLN observation store: one positive Decimal rate per effective date, with publication number and fetched timestamp. Same-date upserts refresh the rate, publication number, and fetch time; later effective dates remain available as history. Generated Ash migration and resource snapshot were applied and reviewed. `ExchangeRateProvider.Result` defines the provider contract, and strict `NbpExchangeRate` uses Req against the HTTPS latest Table A EUR endpoint, decodes the canonical Decimal JSON shape, validates future dates and malformed/non-positive values, and maps transport/status/schema failures explicitly. `ExchangeRateWorker` runs at queue concurrency 1 with active-state uniqueness, retry/cancel behavior, and PubSub completion/failure events. `ExchangeRateAcquisition` subscribes before enqueueing and requests at most once per UTC day based on fetched freshness; weekends and holidays carry forward the latest published rate. Static Cron configuration is `0 15 * * *` UTC. No HTTP runs in LiveView or normal request paths, and the live official adapter smoke observed 4.3010 for 2026-08-07, publication `152/A/NBP/2026`.

`TcgCheap.Operations` now provides a fail-closed external-request admission foundation. `DataProvider` persists a stable provider key, display name, active/disabled kill switch, estimated per-request cost, coherent hourly/daily/monthly request limits, and a provider monthly estimated-spend cap no greater than US$50. `BudgetUsage` retains provider UTC hour/day/month request and estimated-spend counters. `AcquisitionBudget` strictly validates the complete application configuration, preserves disabled database status during config synchronization, normalizes UTC window boundaries to whole seconds, and uses one PostgreSQL advisory lock plus one transaction to lock/upsert the provider, aggregate provider/global usage, reject a limit, and atomically increment all three windows. Global hourly/daily request limits and global monthly estimated-spend are shared across providers, so concurrent admissions cannot pass stale counters.

Operational request callbacks are injected into TCGdex catalogue `Importer`/`Sync`/`Enrichment`, the TCGdex Cardmarket valuation worker, the NBP worker, and the sealed-retailer worker. Each in-tree adapter invokes the callback immediately before every outbound request; LootQuest invokes it per page. Metered paths force Req retries off, so Oban or an explicit caller owns retry and each later HTTP attempt must be admitted separately. Rejection prevents HTTP, persisted disable remains effective, malformed admission wiring fails closed, and budget database failure is retryable in workers without provider invocation. Generated migration/snapshot sets `20260809023642`–`20260809034324` create provider/counter persistence, coherent constraints, provider-window uniqueness, and the global-window lookup index. This records estimated reservation only: actual paid-cost reconciliation, public per-IP acquisition throttling, acquisition priority classes, source-health/circuit-breaker automation beyond the manual kill switch, and admin usage/failure inspection remain incomplete.

The repository is developed in a Nix devenv with Elixir, PostgreSQL, Podman/Compose, Worktrunk, Tailwind, and esbuild tooling. The historical provider-neutral singles core exists in `lib/tcg_cheap/pricing/singles/provider.ex`, `offer.ex`, and `valuation.ex`, with focused tests in `test/tcg_cheap/pricing/singles/provider_test.exs` and `valuation_test.exs`. `Provider`/`Offer`/`Valuation.default_v1` remain historical/post-MVP seller-level capability; `Offer` normalizes seller/language/condition/shipping/Decimal EUR fields and `Valuation` calculates five-lowest-distinct-seller values. The active aggregate adapter uses Req against the fixed TCGdex card endpoint, Jason Decimal decoding, deterministic metric selection, half-up two-decimal rounding, `tcgdex_cardmarket_v1` provenance/timestamps/Cardmarket ID, safe bounded retries, tagged errors, and server-side configuration. Valuation acquisition is integrated through Oban 2.23 with a valuations queue (concurrency 4) and seven-day Pruner; `ValuationAcquisition` creates freshness-gated, deduplicated exact-printing jobs. Its worker validates identity, policy, EUR value, and provenance; fetches outside transactions; records through the existing snapshot action with active uniqueness; classifies retryable versus permanent failures; and broadcasts card-specific success and terminal-failure PubSub events. A subscribe-before-request helper closes the LiveView race. No provider call runs on a public render path.

The active TCGdex aggregate intentionally has no seller/offer count field. The public UI must show source plus selected metric/methodology, not an unknown-count widget; no count may be fabricated, and a future shared storage field may be nullable/optional. Scraper paths remain post-MVP research, with broader seller-level acquisition and destination-eligibility validation still open.

Strict TCGdex set enumeration and brief-card sync fetch provider payloads outside writes, validate counts and briefs before one transaction, preserve enriched rows/images, and seed pending minimal cards. Catalogue Sync uses per-set locking and now acquires the same per-card transaction advisory lock as the full importer, sorting brief card IDs before locking. This closes the intermittent brief/full unique-ID race and prevents lock-order cycles across overlapping sets. Provider fetches remain outside transactions. Cross-set conflicts are rejected atomically; TCG Pocket sets are excluded as designed. The one-card importer also uses `FOR UPDATE` and source/mapping timestamps to reject stale responses. Import and brief sync consistently acquire PostgreSQL advisory locks set-before-card; real concurrent Sync plus fetched Importer coverage passed 20/20 repetitions.

Mapping is conservative: only one explicit Cardmarket ID with no material ambiguity is matched; first-edition, `wPromo`, stamps, pre-release, jumbo, special foil, nonstandard-size or material subtypes, multiple material identities, and multiple Cardmarket IDs are review states with no guessed ID. Finish-only normal/reverse/holo differences may be simplified. `TcgCheap.Catalogue.Enrichment.enrich_set/2` fetches one detailed set, validates exact identity and canonical card lists before writes, then fetches each card at most once with ordered bounded concurrency and imports successful payloads under one shared normalized UTC microsecond timestamp. It rejects malformed/truncated lists, duplicate/invalid IDs, and fan-out above 1,000 before card calls; unexpected callback outcomes and timeouts are isolated so later cards continue. The importer exposes `import_fetched_card/4` with explicit expected IDs and an import/stale outcome while preserving `import_card/2`'s public card return. Cross-set reassignment, including stale payloads, is rejected; existing `CardSet` metadata is preserved during card enrichment, while set sync owns subsequent metadata refresh and can create missing sets. Reruns are idempotent and stale provider card/mapping data is preserved. `SingleValuationSnapshot` retains positive EUR aggregate valuations, policy/source/metric provenance, fetched and provider-update timestamps, optional Cardmarket product ID, and immutable current/archive state. `record_single_valuation` locks the parent `CardPrinting` with `FOR UPDATE`, archives only the prior current snapshot for the exact card and policy, and inserts the replacement. Policy-specific history is preserved, and seven-day freshness classification remains defined.

Local exact-printing search is exposed as `TcgCheap.Core.search_card_printings`. Private persisted fields derive from name, set, collector number, and TCGdex ID through shared Unicode NFKC, whitespace collapse, trim, and lowercase normalization; SQL backfill parity uses PostgreSQL 18 `pg_unicode_fast`. Four concurrent GIN trigram indexes support escaped contains and `%` candidates. Ranking is deterministic and bounded (exact IDs/names/collectors/sets, prefixes, similarities, Standard legality tie-break, stable identity); default 10, hard max 20, effective minimum 2. All mapping statuses and non-Standard cards remain searchable; exact printings are never collapsed and `CardSet` is loaded.

`/` is now a public local-only exact-printing search surface in `HomeLive`. It uses the shared external 250ms `CardAutocomplete` hook used by Home and Trade, backend-shared normalization, effective minimum 2/max 100 handling, and LiveView stream resets. The focused input is never server-value patched: query, node, focus, caret/selection survive result updates; composition pauses search until compositionend and Escape cancels debounce. Idle, short, invalid, empty, error, and results states have stable accessible IDs and `aria-live`; same-count result updates still change the query-specific status. Same-name printings remain separate and show original name/set/collector plus optional rarity; exact TCGdex identity remains in internal routing/data. No provider HTTP runs from render/event paths and no price is invented. Current commit `52a9c0d` renders approved TCGdex imagery only through the strict `CardImage` boundary: canonical `https://assets.tcgdex.net` URLs, low WebP search images, no-referrer, exact CSP host, no proxy/cache, and honest missing/invalid fallback.

Home now uses a scoped `decision-world`: a bright card-shop valuation bench distilled for ordinary collectors with warm bench/paper/ink/orange tokens, square rules, Barlow Condensed action hierarchy, Azeret Mono supporting copy, an accessible Singles/Sealed switch, and category-specific direct search. Singles rows show image, name, set, collector number, optional rarity, `€…` or `Price unavailable`, `Updated …` plus `May be outdated`, and one solid `View price` CTA. Sealed rows use canonical identity, type, series/set, release date, discontinued state, an honest no-image placeholder, and one `View offers` action. Full policy/methodology/non-affiliation caveats are collapsed under `How prices work`; rows avoid provider/policy/local-data jargon. Singles remains the default. The active `tcgdex_cardmarket_v1` valuation is loaded with Singles search in one relationship load, with no N+1 valuation read. The `archive-world` remains scoped to card detail and was not removed globally. Generic shared Layout remains neutral.

Public Sealed is now a local-only foundation. `SealedProduct.search_public` normalizes a bounded query, searches approved canonical names and approved name aliases, uses concurrent GIN trigram indexes plus deterministic exact/alias/prefix/similarity ranking, and never exposes drafts, future releases, unofficial/non-PL/non-English rows, or EAN aliases. Stable streamed options share the focus-preserving autocomplete behavior; Enter carries the current input value, and Home plus Trade reject stale cached selections. `/sealed/:slug` reads approved local identity and matched evidence only. `PublicSealedProductProjection` selects one cheapest in-stock listing per active shop and one most recently checked sold-out listing per shop within 30 days, then sorts current offers by Decimal PLN and sold-out evidence chronologically. Detail shows optional provenance-backed MSRP, release/distribution status, shop category, stock, UTC last check, direct HTTPS link, shipping exclusion, separate current/sold-out empty/error states, and explicit **Limited data** instead of inventing a benchmark, graph, confidence, or buying bands. No provider HTTP runs in public paths.

The public `/cards/:tcgdex_id` exact-printing detail is now linked from local search. It is local-first: the initial render and events read the local printing and current valuation, while a disconnected/static local valuation and bounded-history read remains useful without a provider. When freshness requires work, the LiveView subscribes before requesting the deduplicated Oban acquisition; card-specific PubSub completion and terminal-failure events reconcile the final state. The current value is preserved independently when the history read fails. The surface explicitly represents fresh, stale, fetching, unpriced, read-error, and terminal-failure states, with an insufficient-history collecting state until real observations accrue.

History is a fixed 30 UTC-calendar-date query/projection: at most the latest fetched/created observation with a stable ID per day, with no future or older points and gaps left disconnected. Decimal values drive the SVG geometry, alongside an accessible ledger. The detail includes source, metric, policy, timestamp, methodology, and a disclaimer; mobile identity and value come first. Approved TCGdex detail imagery uses high WebP through `CardImage`; invalid or missing assets fall back honestly. The visible disclaimer names Pokémon, Nintendo, TCGdex, Cardmarket, and listed companies. Third-party artwork rights are not independently proven, and broader reuse/self-hosting remains unapproved. Card detail now exposes a side-neutral `Add to a trade` CTA with strict local return/pick reconstruction. The surface brief is `.impeccable/surfaces/lib-tcg-cheap-web-live-card-detail-live-ex.md`.
