# Deployment and operations

TCG Cheap runs as one container (Phoenix web server, Oban jobs and admin in a
single OTP release) next to one PostgreSQL database. There is no deployment
yet; this guide covers the first deployment and day-2 operations. Run one
application instance: the public and login rate limiters are per node.

## Configuration

Required at runtime (`config/runtime.exs`); startup fails without them:

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | `ecto://USER:PASS@HOST/DATABASE` |
| `SECRET_KEY_BASE` | Phoenix secret, generate with `mix phx.gen.secret` |
| `PHX_HOST` | Public hostname; URLs are generated as `https://PHX_HOST` |

Optional:

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `4004` | HTTP listener inside the container |
| `ADMIN_AUTH_SIGNING_SECRET` | `SECRET_KEY_BASE` | Separate admin token signing secret, at least 32 bytes |
| `POOL_SIZE` | `10` | Database connections |
| `ECTO_IPV6` | off | `true`/`1` to connect to the database over IPv6 |
| `DNS_CLUSTER_QUERY` | unset | DNS clustering (not needed for one instance) |
| `SOURCE_COMMIT` | `unknown` | Git SHA reported by the health endpoints (Coolify sets it automatically) |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | — | Only for the one-shot admin provisioning command |
| `MCP_API_TOKEN` | unset | Bearer token for the agent MCP endpoint `/mcp`, at least 32 bytes; unset refuses every MCP request |

The image sets `PHX_SERVER=true`, `PORT=4004` and a UTF-8 locale. Keep secrets
in the platform's secret store, never in the image or the repository.

**TLS and proxy.** The app speaks plain HTTP on `PORT` and expects a reverse
proxy to terminate TLS. Production forces HTTPS (`config/prod.exs`): the proxy
must send `X-Forwarded-Proto: https`, otherwise requests are redirected.
Requests to `localhost`/`127.0.0.1` are exempt, which keeps the container
health check working.

## Database

Use the same pinned ParadeDB image as local development and CI
(`local/compose.yml`, checked by `.github/workflows/ci.yml`):

```text
docker.io/paradedb/paradedb:v0.26.4-pg18@sha256:4abbafffb4e59e679821c5882faf91c494022bb3242fc73b789e753f43df1361
```

- Start it like local Compose does, with
  `-c shared_preload_libraries=pg_search,pg_cron,pg_stat_statements`, on a
  persistent volume.
- The application needs PostgreSQL ≥ 18.4 (`TcgCheap.Repo.min_pg_version/0`)
  and only the `citext` and `pg_trgm` extensions plus Ash SQL functions, which
  the migrations create. The migration role must be allowed to create
  extensions and functions. ParadeDB's `pg_search` and vector features are not
  used.
- LiveDashboard's Ecto Stats "Calls" and "Outliers" views need
  `pg_stat_statements`; no migration creates it. Run
  `CREATE EXTENSION IF NOT EXISTS pg_stat_statements;` once if you want them.

## Build

```sh
docker build -f deployment/Containerfile.app -t tcg-cheap:release .
# or: podman build --format docker -f deployment/Containerfile.app -t tcg-cheap:release .
```

The image runs as a non-root user, exposes port 4004, has a `HEALTHCHECK`
on `/health`, and starts with `/app/bin/tcg_cheap start`. CI builds the same
file on every push and pull request.

## Production (Coolify + Infisical)

Production runs at <https://tcg.cheap> on the Alergeek Coolify
(`coolify.alergeek.me`, project *TCG Cheap*): the application `app` built from
`deployment/Containerfile.app` on `main`, and the database `psql` with the
image above (its volume mounts at `/var/lib/postgresql`, as PostgreSQL 18
images require). Cloudflare proxies the `A` record to the Coolify server.

Configuration lives in Infisical (`infisical.alergeek.me`, project
`tcg-cheap`, environment `prod`, path `/app`): `DATABASE_URL` (the database's
internal URL), `SECRET_KEY_BASE`, `PHX_HOST=tcg.cheap` and `MCP_API_TOKEN`.
Change values there, never in Coolify: every deployment overwrites the
application's variables with them.

**Deploying.** Every push to `main` runs CI; after `mix check` and the
container build pass, the `deploy` job (GitHub environment `production`, main
only) uses the `av-secret-service` `coolify-deploy` action: it logs in to
Infisical over GitHub OIDC (machine identity *tcg-cheap github actions*,
read-only on this project), syncs `prod:/app` to Coolify, deploys and waits.
The new container runs pending migrations as it starts, before Oban and the
endpoint; a failing migration keeps it unhealthy, Coolify rolls back and the
old container keeps serving. Migrations are generated by Ash and run forward
only; if one is wrong, ship a new one. To redeploy without a commit, re-run
the workflow on `main`.

The `production` environment holds `INFISICAL_MACHINE_IDENTITY_ID`,
`COOLIFY_APP_UUID` (variables), `COOLIFY_TOKEN` and
`AV_SECRET_SERVICE_DEPLOY_KEY` (a read-only deploy key of the private
`av-secret-service` repository, needed because this repository is public).

**First administrator.** Once, in the Coolify terminal of the running
application (the password needs at least 14 characters and is never
printed):

```sh
ADMIN_EMAIL=… ADMIN_PASSWORD=… /app/bin/tcg_cheap eval 'TcgCheap.Release.provision_admin()'
```

Then load the first data ([First data](#first-data)), sign in at
`/admin/sign-in`, open `/admin/buying-guide` and check that every shop has a
recent fetch and the home page lists products with prices.

## Background jobs

All schedules are UTC, defined in `config/config.exs` (Oban Cron). Each queue
runs one job at a time; completed jobs are pruned after 7 days.

| Schedule | Worker | Queue | What it does |
| --- | --- | --- | --- |
| 03:00 daily | `TcgCheap.Pricing.CardmarketBulk.SyncWorker` | `cardmarket_bulk` | Cardmarket singles files → card valuations |
| 03:30 daily | `TcgCheap.Sealed.CatalogueImportWorker` | `sealed` | Cardmarket sealed catalogue and prices |
| 04:00 daily | `TcgCheap.Sealed.FetchWorker` (no shop) | `sealed` | Queues one `FetchWorker` job per shop in `TcgCheap.Sealed.Shops`; the queue fetches them one after another (1–22 s each; all 71 took about 5 minutes on 2026-10-31) |
| 15:00 daily | `TcgCheap.Pricing.ExchangeRateWorker` | `exchange_rates` | NBP EUR/PLN rate |
| every 15 min (unique per week) | `TcgCheap.Catalogue.SinglesCatalogueBootstrapWorker` | `catalogue_sync` | Queues the TCGdex catalogue sync and card detail enrichment |
| every 15 min (once per manifest) | `TcgCheap.Catalogue.CuratedPlayableBootstrapWorker` | `catalogue_sync` | Curated playable cards; no-op after 2026-11-17 |
| every 15 min | `TcgCheap.Operations.AcquisitionReconcilerWorker` | `operations` | Repairs stranded acquisition runs |

Sealed jobs get up to 3 attempts; a failed fetch or import writes nothing, so
the previous data stays in place. Offers from a shop stop counting when the
shop has not been fetched successfully for 3 days. TCGdex, Cardmarket singles
and NBP requests are limited by the acquisition budget in `config/config.exs`
and visible at `/admin/operations`.

Inspect jobs at `/admin/oban`. Do not leave a queue paused: `/health` reports
unhealthy while any configured queue is paused.

## First data

A new database is empty until the jobs run. Queue them on the running
container in this order, e.g. from the Coolify terminal with
`/app/bin/tcg_cheap rpc '…'` (each command returns at once; the jobs run in
the background). The sealed jobs can also be queued by an agent over MCP
(`enqueue_catalogue_import`, `enqueue_shop_fetch`):

```sh
/app/bin/tcg_cheap rpc 'TcgCheap.Pricing.ExchangeRateAcquisition.enqueue()'
/app/bin/tcg_cheap rpc 'TcgCheap.Sealed.CatalogueImportWorker.enqueue()'
/app/bin/tcg_cheap rpc 'Enum.each(TcgCheap.Sealed.Shops.keys(), &TcgCheap.Sealed.FetchWorker.enqueue/1)'
```

The `sealed` queue runs them one after another, catalogue first. For singles,
use the manual refresh buttons on `/admin/operations` (TCGdex catalogue,
scoped singles collection, NBP) and queue the Cardmarket bulk sync after the
catalogue has cards:

```sh
/app/bin/tcg_cheap rpc 'TcgCheap.Pricing.CardmarketBulk.SyncWorker.new(%{}) |> Oban.insert()'
```

Until a product has 7 days of shop prices, its verdict uses the Cardmarket
trend; this is expected.

## Day-2 tasks

### Check the buying guide

`/admin/buying-guide` shows, per shop, the last successful fetch, offers seen,
matched offers and matched offers in stock, then the current unmatched offers,
the automatically matched offers and the manual decisions. A shop whose last fetch is older than a day has a
failing job: look for its `FetchWorker` job in `/admin/oban` and the
`sealed fetch <shop> failed` log line.

To re-run one shop or the catalogue import immediately:

```sh
/app/bin/tcg_cheap rpc 'TcgCheap.Sealed.FetchWorker.enqueue("lootquest")'
/app/bin/tcg_cheap rpc 'TcgCheap.Sealed.CatalogueImportWorker.enqueue()'
```

### Fix an unmatched or mismatched offer

- **Unmatched offer:** in `/admin/buying-guide`, click *Assign…* next to it,
  search for the product and choose it. Prices, availability and today's
  daily price are recomputed at once. Automatic matching never overrides it,
  and its EAN then matches the same product in other shops and opens it
  from the public search or barcode scanner.
- **Wrong automatic match:** find the offer in *Matched offers* (filter by
  title), then either *Reassign…* it to the right product or choose
  *Never match* to keep it out of every verdict.
- **Wrong manual decision:** click *Clear* in the manual list; the offer
  returns to automatic matching.

  If the same mistake repeats, fix the rule in `TcgCheap.Sealed.Matcher`
  (synonyms, qualifiers, exclusions); every shop fetch re-matches
  all automatic offers.

### Let an AI agent do it

`/mcp` is an MCP server (streamable HTTP) with the same work as tools: shop
status, unmatched/matched offers and manual decisions, product search and
detail, `explain_match` (why a title matches or not), assign/exclude/clear,
`set_product_eans` and queuing a shop fetch or catalogue import. Its
instructions tell the agent to leave an offer alone when unsure.

In production, set `MCP_API_TOKEN` and give the agent the header
`Authorization: Bearer <token>`. The development server, like Tidewave,
listens only on localhost and needs no token; `.mcp.json` (Claude Code) and
`opencode.json` already point at it.

### Add or remove a shop

A shop must expose a public feed with a client in `TcgCheap.Sealed`: the
WooCommerce Store API (`/wp-json/wc/store/v1/products`), Shopify's
`/products.json`, a Shoper export (`GoogleFeed` for
`/console/integration/execute/name/GoogleProductSearch`, `CeneoFeed` for
`…/CeneoV2`; a Shoper shop without the integration answers with an empty
body) or IdoSell's `getProductXML=t` listing view, or else a category
listing one of the listing clients reads (`PrestaShop`, `ShoperListing`,
`SkyShop`, `ShopGold`, `Sellingo`, `Selly`, `Sote`), with prices in PLN, and
its `robots.txt` must allow it; a shop behind a bot challenge is left out.
Whole-shop exports may be up to 64 MB.

1. Add a `%TcgCheap.Sealed.Shop{}` entry to `TcgCheap.Sealed.Shops`: key,
   name, host, `source` and `max_pages`; for WooCommerce the Pokémon category
   id(s) (`/wp-json/wc/store/v1/products/categories?per_page=100`), optional
   sealed category slugs and the permalink pattern; for Shopify an optional
   Pokémon collection handle; for Shoper the export path (`@shoper_google` or
   `@shoper_ceneo`) as `feed_path` and `max_pages: 1`; for IdoSell the
   Pokémon category or search path (query included, without `getProductXML`)
   as `feed_path` and a page limit; for a listing client the Pokémon
   category path as `feed_path` (Shoper, Sky-Shop; for Shoper
   `mixed_listing: true` when the category holds other games and
   `preorder_path` when the shop lists its pre-orders separately) or the category paths as
   `listing_paths` (PrestaShop, shopGold, Sellingo, Selly, SOTE), and a page
   limit. Add the delivery facts from the shop's delivery
   page (cheapest delivery, free-delivery threshold, pickup city; nil when not
   published) and, for a pickup store, its `pickup_location` coordinates.
   Optionally add its logo as `priv/static/images/shops/<key>.webp`: the
   shop's own logo, trimmed and fitted into 228×68 on a 240×80 white chip
   (dark `#2b2925` for a light logo).
   Image hosts and the CSP follow automatically, and the daily job
   picks the shop up.
2. Run `mix check`, fetch the shop in the running app (`enqueue_shop_fetch`
   over MCP or `FetchWorker.enqueue/1`), check `shop_status` and its
   unmatched offers, and deploy.

To remove a shop, delete its entry and deploy; its offers stop counting
within 3 days, and its stored history stays.

### Singles

- `/admin/operations`: provider health, budgets, recent runs and manual
  refreshes for TCGdex and NBP.
- `/admin/catalogue/cards`: inspect printings; correct a Cardmarket mapping
  at `/admin/catalogue/cards/:id/correct`.
- `/admin/operations/import-issues`: TCGdex import problems; failed sets can
  be retried from `/admin/operations`.

### Monitoring

- `/admin/dashboard`: Phoenix LiveDashboard with metrics, Ecto Stats, request
  logger and live logs (only while open).
- `/admin/oban`: queues, jobs, cron entries, retries.

## Health

| Endpoint | Meaning | Status |
| --- | --- | --- |
| `/health/live` | The web process answers | always `200` |
| `/health` | Database answers, Oban runs with every queue unpaused, acquisition budget is configured | `200` healthy, `503` otherwise |

Both return JSON with `status`, `timestamp` and `revision` (`SOURCE_COMMIT`
or `unknown`); `/health` adds per-check results (`queue_count`,
`provider_count`). Neither calls an external service. The container
`HEALTHCHECK` uses `/health`; wire the platform's readiness check to it too.

## Backups

Coolify dumps the `tcg_cheap` database daily to the *OVH S3 new backups*
storage (the database's *Backups* tab). Test a restore into a separate
database regularly. By hand:

```sh
pg_dump --format=custom --file=tcg_cheap-$(date +%F).dump "$DATABASE_URL_PG"
pg_restore --clean --if-exists --no-owner --dbname="$TARGET_DATABASE_URL_PG" tcg_cheap-YYYY-MM-DD.dump
```

(`pg_dump` needs a `postgres://` URL, not the `ecto://` form.) What cannot be
re-fetched: the daily price history (`sealed_daily_prices`) that drives the
30-day verdicts, manual offer assignments, singles valuation history and
mapping decisions, and administrator accounts. The catalogue, offers and
current prices are rebuilt by the next jobs. Restore with the application
stopped; starting it migrates the restored database.
